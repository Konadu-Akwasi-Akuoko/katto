# Phase 7 — Browser, Thumbnails, Resolve, Import & Ship Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (or
> superpowers:subagent-driven-development) to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the workflow loop — an in-app multi-tab browser whose downloads file
themselves into project `assets/` with license sidecars, PSD thumbnail scaffolds with a PNG
folder watch, a Resolve Studio scripting-API import, the one-time studio.db idea import — then
the design-polish pass and an installable `.dmg` (PRD: `prd/phase-7.md`).

**Architecture:** All browser machinery lives in the app crate (`src-tauri/src/browser.rs` +
`browser/`) because tabs/downloads are app orchestration, not media math; `katto-engine` gains
nothing this phase except reuse of `timelines` version scanning. The browser rides tauri's
`unstable` multi-webview API: the existing `main` window (a `WebviewWindow`) is fetched as a
`Window` via `Manager::get_window` and child webviews are attached with `Window::add_child` —
one child per tab, **only the active tab's webview shown** (macOS bug tauri#11376 sidestep).
All tab/history logic is a pure `TabModel` shared by both `BrowserTabHost` impls
(multi-webview + single-reused-webview fallback behind a settings flag). Download filing,
unzip safety, sidecar JSON, thumbnail naming, PSD template bytes, Resolve script generation,
and studio.db row mapping are all pure functions, TDD'd; webview/subprocess/watch spawn sites
stay thin.

**Tech Stack:** Rust 2024 (tauri `~2.11` + `unstable` feature, zip 8.6, existing notify 8.2 /
rusqlite 0.40), React 19 + TS + Tailwind v4, tauri-specta `=2.0.0-rc.25`, vitest + RTL, bun.

## Locked design decisions (decided now — do not re-litigate)

1. **Downloads stage-then-file.** `Requested` always rewrites `destination` to
   `<app_data>/browser/staging/<uuid>/<filename>`; filing into
   `<project>/assets[/envato]/` happens as a job **after** `Finished{success: true}`.
   Rationale: (a) macOS never reports the finished path, so katto must own the destination
   anyway; (b) no partial file ever appears inside a project folder (atomic-artifact
   invariant); (c) staging→assets is a plain move the filing job fully controls (unzip,
   sidecar, dedupe, events). This intentionally refines the PRD's "rewrites destination into
   `<active project>/assets/`" — same user-visible outcome, strictly safer intermediate
   state. Cross-device moves (app-data on boot volume → studio root on SSD) fall back from
   `fs::rename` to copy+remove.
2. **No-active-project = park, then sheet.** If no project can be resolved at `Finished`
   time (fresh install, no projects), the download stays parked in staging, a
   `DownloadNeedsProject` broadcast opens the picker sheet, and
   `file_parked_download(download_id, slug)` files it. Deny-and-retry (the PRD's "before
   accepting" reading) is fragile — re-triggering a consumed download link re-navigates the
   tab and breaks blob/signed URLs. Parking preserves the bytes and still never touches
   `~/Downloads`.
3. **`~/Downloads` fallback is only for interception blind spots** (blob:/data: URL
   downloads, which WKDownload may hand over without a `Requested` we can redirect
   usefully): katto leaves the destination untouched, records events kind
   `download_fallback`, and broadcasts a persistent notice banner (PRD D16). Blob downloads
   against Envato specifically are an owner checkbox.
4. **Tab titles derive from the URL** (host without `www.` + prettified last path segment) —
   the multi-webview API exposes no page title and remote webviews have no IPC to report
   one. Pure fn, unit-tested; the address bar shows the real URL, titles are cosmetic.
5. **Session persistence = WKWebView default data store.** All tabs share the app's default
   persistent cookie/localStorage store (Envato login survives restarts and window
   destroy/recreate). `data_store_identifier` and `incognito` stay unused. The main app
   webview shares the store harmlessly (localhost origin).
6. **`BrowserTabHost` is a trait with two impls** (PRD): `MultiWebviewHost` (one child
   webview per tab) and `SingleWebviewHost` (one reused child webview; select = navigate;
   history fully model-driven). Settings key `browser_single_webview` (`"false"` default)
   picks the impl at setup; flipping it requires an app relaunch (documented in the Settings
   copy). Both impls delegate every tab/history decision to the shared pure `TabModel` —
   contract tests run against the model, spawn sites stay thin (testing rules).
7. **Child webviews die with the main window (D21 close-to-tray destroys it).** The host
   keeps `TabModel` + desired bounds/visibility in `AppState`; webviews are (re)created
   lazily on the next `browser_set_visible(true)` / tab op, and `WindowEvent::Destroyed`
   clears the host's webview handles. Tabs survive window recreation; page state (scroll,
   form input) does not — same cost the PRD accepts for the fallback impl.
8. **Active asset project = explicit override, else `most_recently_touched`.**
   `set_active_asset_project(slug?)` stores the override in `AppState`
   (`Mutex<Option<String>>`); `None` clears back to the derived default. The downloads
   popover shows the current target and offers the switcher.
9. **Envato routing rule:** a download whose *source URL or page URL* host is `envato.com`,
   `*.envato.com`, or `*.envatousercontent.com` (the real download CDN) files under
   `assets/envato/`; everything else under `assets/`. Pure fn, table-tested.
10. **Only `.zip` counts as an archive** (Envato Elements delivers zips). Other extensions
    file as plain files. Unzip flattens a single top-level directory (Envato zips wrap one
    folder) — pure `single_root` helper decides from entry names. Unzip failure keeps the
    archive in place (already moved into `assets/…`) and the sidecar records
    `"unzip_failed": "<error>"` (PRD error-handling row).
11. **Thumbnail templates are generated once by katto's own pure PSD writer and committed as
    bundled resources.** The PRD's "bundled PSD (no PSD crate — copy only)" assumed the
    owner authors templates in Photoshop; the owner is asleep. A minimal flattened PSD
    (8BPS v1, RGB 8-bit, RLE white canvas) with **Photoshop guide resources** (image
    resource 0x0408) at the safe-zone lines is fully writable as pure bytes — ~200 lines,
    TDD'd against a mini-parser. Runtime behavior stays exactly PRD: copy the bundled
    resource, never edit PSDs. The owner can replace the committed `.psd` files with
    hand-authored ones later (same filenames). An `#[ignore]`d generator test writes
    `src-tauri/resources/thumbnail-templates/{thumb-1280x720,thumb-1080x1920}.psd`.
    **[VERIFY at implementation: skim the Adobe PSD format spec section on the header,
    image-resource blocks (0x0408 grid/guides: version 4? — the spec states version and
    fixed-point guide coordinates), and RLE image data before writing bytes.]**
12. **Scaffold letters run a…z, then aa, ab…** (spreadsheet-style), scanning existing
    `<slug>-thumb-<letters>.psd` names; `create_new` semantics — a name collision is a bug
    surfaced, never an overwrite.
13. **One thumbnails watch at a time** (the open project detail): `watch_thumbnails(slug)`
    replaces the previous watcher (notify `recommended_watcher`, NonRecursive on
    `<project>/thumbnails/`, 500 ms hand-rolled debounce thread like `volumes.rs`), broadcasts
    `ThumbnailsChanged { slug }`. Watcher death → events row `thumbnail_watch_failed`, never
    a crash. Project cards use a one-shot `list_latest_thumbnails()` scan (cheap: one
    readdir per project), invalidated by the same broadcast.
14. **Resolve bridge = generated Python on stdout-JSON.** katto writes a temp script,
    spawns `/usr/bin/env python3` with the three env vars, 60 s timeout, parses a single
    JSON line: `{"ok": true, "project": …}` or `{"error": "not_connected" | "create_failed"
    | "import_failed", "detail": …}`. Preflights (in order, each a typed error): Resolve app
    bundle present (`resolve_not_installed`), Resolve process running — `pgrep -x` both
    `"DaVinci Resolve"` and `"Resolve"` process names (`resolve_not_running`), python3
    present. `not_connected` from a running Resolve maps to `resolve_scripting_unavailable`
    whose message names both remedies: enable *Preferences → System → General → External
    scripting using: Local*, and "DaVinci Resolve **Studio** is required — the free edition
    does not support external scripting" (D12). Script generation and stdout parsing are
    pure + snapshot-style tested; the spawn site is thin.
15. **studio.db apply runs as a job** (kind `studio_import`) with the report delivered via a
    `StudioImportFinished` broadcast + `studio_imported` events row; dry-run is a plain
    command returning `ImportReport` synchronously. Import normalizes `first_seen` to
    `YYYY-MM-DDTHH:MM:SSZ` (both source shapes), maps `new|keep→backlog`,
    `rejected→discarded`, `promoted→promoted` (unknown status → skipped + warning), and
    upserts by `id` via a new `db::ideas::upsert_imported` (INSERT when absent; UPDATE all
    15 non-id columns when different; `Unchanged` when identical — counted as skipped).
    Settings key `studio_import_last_run` (ISO timestamp) renders the "already imported
    on …" note; re-running stays allowed (idempotent by construction).
16. **New error kinds** in `error.rs` (unit variants, snake_case on the wire):
    `browser_unavailable` (multi-webview op failed / window gone), `download_missing`
    (parked id not found), `unzip_failed`, `resolve_not_installed`, `resolve_not_running`,
    `resolve_scripting_unavailable`, `resolve_failed`, `import_failed`,
    `photoshop_missing` is NOT an error — Photoshop absence falls back to reveal-in-Finder
    inside the command and reports which happened via the return value (PRD: PSD still
    scaffolds).
17. **New events kinds** (snake_case, matching the majority convention): `asset_filed`,
    `download_failed`, `download_fallback`, `thumbnail_scaffolded`,
    `thumbnail_watch_failed`, `resolve_imported`, `studio_imported`,
    `browser_fallback_engaged` (single-webview flag flipped on after a multi-webview
    failure).
18. **Design-polish pass adds the missing motion tokens** (`--ease`, `--dur-fast`, `--dur`,
    `--dur-slow`) to `@theme` and retrofits the literal durations logged as design debt in
    the phase 3–5 run (`duration-300` in plan-steps etc.); plus focus-ring, reduced-motion,
    empty-state-copy, cursor, tabular-nums, and grain-on-translucent audits. No functional
    changes (PRD).
19. **Packaging ships `["app", "dmg"]` targets** with `minimumSystemVersion: "13.0"`,
    bundles `resources/thumbnail-templates/`, adds a `just dmg` recipe, and documents
    signing stubs in `docs/packaging.md`. The final build runs locally
    (`bun run tauri build --bundles app,dmg`) and the artifact path is recorded in
    `docs/overnight-run.md`. No release/version-bump commit — the owner reviews first.

## Design grounding (Dribbble pass, 2026-07-22)

Searches: "in app browser tabs", "browser app dark ui", "download manager dark",
"asset library manager dark" (the first and last returned mostly mobile mockups — noted, not
forced). Two shots studied closely.

**Taken:** (a) *DownloadZone* download-popover pattern — downloads live in a quiet popover
anchored to a toolbar button: each row is `filename → thin 4px progress track → muted meta
chips`, a completed row swaps the bar for reveal-in-folder + dismiss actions, a failed row
strikes the name and offers retry; katto's popover reuses exactly this row anatomy with
katto tokens (ember fill, `--failed` on failure) and adds the filing target ("→ sprint-recap
· assets/envato") as the muted meta line, since *where it filed* is katto's whole point.
(b) *Surfe* minimal-nav — section labels stay quiet (`--fg-faint`, sentence case), rows are
28–32px with 16px icons; the tab strip follows: compact 32px tabs, active tab = surface step
+ hairline, not accent-colored.

**Rejected:** neon purple/blue accents and speed-rate chips (katto stays warm-neutral +
ember; download rate is unavailable from the API anyway — no fake telemetry); browser-chrome
skeuomorphism (traffic lights, rounded fake window) — the browser is a katto surface, not a
pretend Chrome; favicon fetching (network chatter for cosmetics; the URL-derived title +
globe glyph is honest); mobile-style card grids for downloads.

The `frontend-design` skill was loaded for this pass; its "copy is design material" rule
drives the empty states in Tasks 6/9/12 and the audit in Task 14.

#[cfg(test)]
mod tests {
    use super::*;
    use std::io::Write;

    fn make_zip(entries: &[(&str, &[u8])]) -> tempfile::NamedTempFile {
        let file = tempfile::NamedTempFile::new().unwrap();
        let mut w = zip::ZipWriter::new(file.reopen().unwrap());
        let opts = zip::write::SimpleFileOptions::default();
        for (name, bytes) in entries {
            w.start_file(*name, opts).unwrap();
            w.write_all(bytes).unwrap();
        }
        w.finish().unwrap();
        file

    fn single_root_detects_wrapped_archives() {

        let mixed = vec!["pack/a.mov".into(), "other/b.png".into()];
        assert_eq!(single_root(&mixed), None);
